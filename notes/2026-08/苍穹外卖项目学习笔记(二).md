## 一、`@Controller` 与 `@RestController` 的区别

### 1. 错误现象
```
Could not resolve view with name 'admin/category/page'
```

### 2. 错误原因
`CategoryController` 用了 `@Controller`，但方法返回的是 `Result` 对象。`@Controller` 会把返回值当作**视图名**去解析，Spring 默认取请求路径作为视图名（`admin/category/page`）去找页面，找不到就报错。

### 3. 核心区别

| | `@Controller` | `@RestController` |
|---|---|---|
| 注解组成 | 仅 `@Controller` | `@Controller` + `@ResponseBody` |
| 方法返回值 | 当作**视图名**解析（跳转页面） | 直接**序列化为 JSON** 写回响应体 |
| 典型场景 | 服务端渲染页面（Thymeleaf/JSP） | RESTful API 接口 |

### 4. 源码本质
```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Controller
@ResponseBody   // ← @RestController 就是多了这个
public @interface RestController { ... }
```

### 5. 关键结论
- 前后端分离、只提供接口 → 用 `@RestController`
- 需要返回页面 → 用 `@Controller` + 返回视图名
- `@Controller` + 方法级 `@ResponseBody` 等价于 `@RestController`

## 二、MyBatis Mapper XML 常见问题

### 1. 动态 SQL `<set>` 的逗号问题

**原则：每个字段末尾都加逗号，最后一个字段不加，交给 `<set>` 自动裁剪末尾逗号。**

```xml
<update id="change">
    update category
    <set>
        <if test="name != null and name != ''">
            name = #{name},
        </if>
        <if test="sort != null">
            sort = #{sort},
        </if>
        <if test="status != null">
            status = #{status}
        </if>
    </set>
    where id = #{id}
</update>
```

**易错点：**
- `<set>` 只裁剪**末尾**多余逗号，**不会在中间自动补逗号**
- 中间字段缺逗号会拼出 `type = ?status = ?` → SQL 语法错误

### 2. `Integer` 类型字段不要和 `''` 比较

```xml
<!-- 错误：Integer 和空字符串比较，类型不匹配 -->
<if test="type != null and type != ''">

<!-- 正确：数值类型只判断 null -->
<if test="type != null">
```

### 3. 笔误：`sort != sort`

```xml
<!-- 错误：恒为 false，导致 sort 永远无法更新 -->
<if test="sort != sort and sort != ''">
<!-- 正确 -->
<if test="sort != null">
```

### 4. SQL 中不能随意加分号

```xml
<!-- 错误：分号截断 SQL -->
and name like concat('%',#{name},'%');
<!-- 正确 -->
and name like concat('%',#{name},'%')
```

**原因：** MyBatis 的 `<if>` 是拼接在 `where` 子句中间的，分号是语句结束符，会导致：
```sql
select * from category WHERE name like concat('%',?,'%'); and type =?  -- 语法错误
```

### 5. `like` 拼接不要用双引号包裹 `#{}`

```xml
<!-- 错误：双引号包裹 #{}，易导致参数无法替换 -->
and name like concat('%',"#{name}",'%')
<!-- 正确 -->
and name like concat('%', #{name}, '%')
```

## 三、SQL 中是否使用「库名.表名」

### 结论
数据源 URL 已指定数据库时，**直接用表名即可**。

```yaml
url: jdbc:mysql://localhost:3306/sky_take_out?...   # 已指定库
```

### 什么时候需要写 `库名.表名`
1. 跨库查询（一条 SQL 访问多个库）
2. 多个库有同名表，需消除歧义
3. 程序动态切换库

### 直接用表名的好处
- 可移植性好（数据库改名/分环境部署不用改 SQL）
- 代码更简洁

## 四、`Result` 泛型

### 1. 能不能不填泛型？
能。不填就是"原始类型"（raw type），能编译运行，但 IDE 会黄线警告。

### 2. 为什么建议填具体泛型

```java
public Result<List<Category>> list(Integer type) { ... }
```

- **编译期类型安全**：编译器检查 `data` 字段类型
- **Swagger 文档准确**：前端能看到 `data` 是 `List<Category>` 的完整结构
- **免强转**：不填的话 `getData()` 返回 `Object`，需手动强转

### 3. 关键认知
泛型只在**编译期**起作用（运行时类型擦除）。**不填泛型，运行时 JSON 序列化结果完全一样**——序列化看的是 `data` 实际存放的对象。

## 五、MyBatis 别名配置

### 为什么 `resultType="Category"` 不用写包名？

因为配置了别名包扫描：
```yaml
mybatis:
  type-aliases-package: com.sky.entity
```

MyBatis 启动时扫描该包，把类名（首字母小写）注册为别名：
- `com.sky.entity.Category` → 别名 `Category` / `category`
- `com.sky.entity.CategoryDTO` → 别名 `categoryDTO`

### 补充
- 别名大小写不敏感
- 内置别名：`int`、`long`、`string`、`map`、`list` 等
- 没配置就必须写全限定名

## 六、AOP 核心概念

### 1. AOP 思想
把多个方法里重复的**横切逻辑**（日志、权限、公共字段填充、事务）抽出来单独写，运行时自动"插入"到目标方法。

### 2. 三大核心概念

| 概念 | 英文 | 作用 | 通俗理解 |
|---|---|---|---|
| **切面** | Aspect | 把公共逻辑封装成的模块（一个类） | "日志"功能整体 |
| **切入点** | Pointcut | 指定作用在哪些方法上 | "哪些方法要被拦截" |
| **通知** | Advice | 指定做什么 + 什么时机 | "拦截后执行的动作" |

### 3. 连接点（Join Point）
程序里所有可执行的方法都是连接点，切入点是从中筛选出的那部分。

### 4. 代码示例
```java
@Aspect          // 声明切面
@Component
public class AutoFillAspect {

    // 切入点：匹配 service 层所有方法
    @Pointcut("execution(* com.sky.service.impl.*.*(..))")
    public void serviceMethods() {}

    // 通知：方法执行前
    @Before("serviceMethods()")
    public void before() { ... }
}
```

### 5. 通知的 5 种时机

| 注解 | 时机 |
|---|---|
| `@Before` | 方法执行前 |
| `@AfterReturning` | 正常返回后（能拿返回值） |
| `@AfterThrowing` | 抛异常后 |
| `@After` | 执行完（无论成功/异常，类似 finally） |
| `@Around` | 前后都控制（最强大） |

### 6. 切入点表达式
```java
execution(* com.sky.service.*.*(..))              // 某包下所有方法
execution(* com.sky.service.CategoryService.add(..)) // 指定方法
@annotation(com.sky.annotation.AutoFill)          // 按注解匹配
```

## 七、反射与 AOP 的关系

### 一句话
**反射是 AOP 底层实现的核心技术之一（尤其 JDK 动态代理）。**

### 反射是什么
运行时动态操作类：创建对象、调用方法（`Method.invoke`）、读写字段（`Field.get/set`）。

### 关系链
```
AOP（思想）
  └── 动态代理（JDK 动态代理 / CGLIB）
        └── 反射（Method.invoke 等）
```

JDK 动态代理核心就是反射：
```java
Proxy.newProxyInstance(loader, interfaces, (proxy, method, args) -> {
    // 前置通知
    Object result = method.invoke(target, args);  // ← 反射调用目标方法
    // 后置通知
    return result;
});
```

### 项目里反射的影子
- AOP/动态代理：`Method.invoke`
- `BeanUtils.copyProperties`：反射读写字段
- MyBatis 结果映射：反射 set 字段
- Jackson 序列化：反射读字段
- **Lombok 不是运行时反射**（编译期生成代码）

## 八、自定义注解语法

### `OperationType value();` 是什么？
是**注解里声明属性（成员）的语法**。

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Autofill {
    OperationType value();
}
```

### 关键规则
- 注解定义用 `@interface`（不是 `interface`）
- 方法名 = 属性名，返回类型 = 属性类型
- 没有方法体、不能有参数
- 返回类型只能是：基本类型、String、Class、枚举、注解或它们的数组

### `value` 是特殊属性名
```java
@Autofill(OperationType.INSERT)              // 简写
@Autofill(value = OperationType.UPDATE)      // 等价完整写法
```

### 元注解

| 元注解 | 值 | 含义 |
|---|---|---|
| `@Target(ElementType.METHOD)` | 方法 | 只能贴在方法上 |
| `@Retention(RetentionPolicy.RUNTIME)` | 运行时 | 保留到运行期，AOP/反射才能读到 |

## 九、AOP 切面编程细节

### 1. `Signature` 与 `MethodSignature`

```
Signature（父接口，org.aspectj.lang.Signature）
    └── MethodSignature（子接口，org.aspectj.lang.reflect.MethodSignature）
```

| | `Signature` | `MethodSignature` |
|---|---|---|
| 能力 | `getName()`、`getDeclaringType()` | 额外有 `getMethod()`、`getReturnType()` 等 |

```java
MethodSignature signature = (MethodSignature) joinPoint.getSignature();
// getSignature() 返回父接口 Signature，需强转才能用 getMethod()
```

**为什么强转安全：** 切点匹配的是方法，实际对象一定是 `MethodSignature` 实现类。

### 2. `joinPoint.getArgs()`

返回**被拦截方法调用时传入的实参数组**，类型 `Object[]`。

```java
Object[] args = joinPoint.getArgs();
// 方法 add(CategoryDTO dto)  → args = [dto]
// 方法 startOrStop(Integer status, long id) → args = [status, id]
```

- 按参数声明顺序存放
- `Object` 类型，使用需强转
- `args[0]` 就是第一个实参

### 3. 完整 AOP 字段填充示例

```java
@Before("autoFillPointCut()")
public void autoFill(JoinPoint joinPoint) {
    // 1. 拿方法注解，判断插入还是更新
    MethodSignature signature = (MethodSignature) joinPoint.getSignature();
    Autofill autofill = signature.getMethod().getAnnotation(Autofill.class);
    OperationType operationType = autofill.value();

    // 2. 拿方法实参
    Object[] args = joinPoint.getArgs();
    if (args == null || args.length == 0) return;

    // 3. 约定第一个参数是要填充的实体
    Object entity = args[0];

    // 4. 根据操作类型填充
    if (operationType == OperationType.INSERT) {
        // fill createTime, createUser
    } else if (operationType == OperationType.UPDATE) {
        // fill updateTime, updateUser
    }
}
```
